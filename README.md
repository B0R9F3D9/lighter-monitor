# Lighter Monitor Bot

Telegram-бот для круглосуточного мониторинга открытых торговых позиций и предотвращения рисков ликвидации на **Robinhood Lighter DEX** (`api.rh.lighter.xyz`).

Построен на стеке **Cloudflare Workers (TypeScript) + Cloudflare D1 (SQLite) + grammY**, строго оптимизирован под бесплатный тариф Cloudflare Free.

---

## Возможности

- 📊 **Мониторинг позиций**: вывод сводки по открытым сделкам (`/positions`) с ценой входа, текущей Mark-ценой, размером, UnPnL и процентом до ликвидации.
- ⏱ **Ежеминутный Cron**: фоновый обход уникальных аккаунтов со справедливым Round-Robin по времени последнего опроса (`last_updated_at`).
- 🚨 **Многоуровневые алерты ликвидации**:
  - `CRITICAL_2` (< 2.5% до ликвидации, кулдаун 10 мин)
  - `DANGER_5` (< 5.0% до ликвидации, кулдаун 30 мин)
  - `WARN_10` (< 10.0% до ликвидации, кулдаун 2 часа)
  - Автоматический сброс кулдауна при возвращении в безопасную зону (> 12%).
- 💀 **Детекция закрытия/ликвидации**: персональное отслеживание исчезнувших позиций, находившихся в критической зоне риска.
- ⚡ **Оптимизация под квоты Cloudflare Free**:
  - Не более 20 запросов к Lighter API за тик (пачками по 5 параллельных запросов с таймаутом 2.5 сек).
  - Группировка алертов по пользователю (1 сообщение на пользователя независимо от числа позиций) — исключает ошибку Telegram `429 (1 msg/sec)` и экономит лимит subrequests.
  - Потолок подзапросов зафиксирован на 45 (запас 5 запросов).
  - Пакетные транзакции `db.batch()` в D1 (расход записи ~28.8% от суточного лимита).

## Команды бота

- `/start` — приветствие и главное меню с инлайн-кнопками.
- `/add <index> [alias]` — добавить аккаунт для отслеживания (до 10 на пользователя).
  - _Пример:_ `/add 31704 Основной`
- `/remove <index>` — удалить аккаунт из списка.
  - _Пример:_ `/remove 31704`
- `/list` — список всех отслеживаемых аккаунтов с алиасами.
- `/positions [index]` — текущие сделки и риски ликвидации по всем (или конкретному) аккаунту.

## Локальная разработка и тестирование

### 1. Установка зависимостей

```bash
bun install
```

### 2. Инициализация локальной базы D1

```bash
bun run d1:init
```

### 3. Запуск тестов

```bash
bun run test
```

### 4. Проверка типов TypeScript

```bash
bun run typecheck
```

### 5. Локальный запуск воркера

```bash
bun run dev
```

## Развертывание в Cloudflare (Production)

### 1. Создание удаленной базы данных D1

```bash
bunx wrangler d1 create lighter-db
```

Скопируйте полученный `database_id` в `wrangler.toml`:

```toml
[[d1_databases]]
binding = "DB"
database_name = "lighter-db"
database_id = "ваш-id-базы-данных"
```

### 2. Применение схемы к удаленной базе

```bash
bunx wrangler d1 execute lighter-db --remote --file=./schema.sql
```

### 3. Установка секретов воркера

```bash
# Токен бота из @BotFather
bunx wrangler secret put TELEGRAM_BOT_TOKEN

# Произвольная секретная строка для защиты вебхука
bunx wrangler secret put TELEGRAM_SECRET_TOKEN
```

### 4. Деплой воркера

```bash
bun run deploy
```

### 5. Привязка вебхука Telegram

```bash
curl -F "url=https://<ВАШ_ВОРКЕР>.workers.dev" \
     -F "secret_token=<ВАШ_TELEGRAM_SECRET_TOKEN>" \
     "https://api.telegram.org/bot<ВАШ_TELEGRAM_BOT_TOKEN>/setWebhook"
```

Для проверки статуса вебхука:

```bash
curl "https://api.telegram.org/bot<ВАШ_TELEGRAM_BOT_TOKEN>/getWebhookInfo"
```
